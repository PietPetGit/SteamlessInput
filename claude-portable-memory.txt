CLAUDE PORTABLE MEMORY
======================

WHAT IT DOES
------------
Claude Code normally stores a project's memory under your Windows user profile,
so resetting Windows and copying the project over loses it. This moves the
memory INTO the project and leaves a junction (folder-pointer) behind, so
Claude Code still reads the same path but the files live with your code.

  BEFORE:
    Claude Code -> ~\.claude\projects\<key>\memory\   = THE REAL FILES
                   (<project>\ has no memory folder at all)

  AFTER:
    Claude Code -> ~\.claude\projects\<key>\memory\   = JUNCTION
                   (empty shell, holds no files itself -- every read/write
                    that touches it is auto-forwarded straight through to:)
                -> <project>\.claude\memory\           = THE REAL FILES


HOW TO USE
----------
Copy this script into a project's root folder, run it, and pick 1.

    cd C:\path\to\project
    .\claude-portable-memory.ps1

That is the whole thing. Do it once per project you want to keep.

Option 1 is the only setup action there is. It is not a repeated step --
it does whatever the project currently needs: on a fresh project it moves
the memory in and links it; on a project that already carries its memory
(after a Windows reset) it just remakes the pointer.


  After resetting Windows:
    - Copy your project folder(s) over. The memory rides inside them.
    - Install Claude Code and log in.
    - Run the script in the project and pick 1.

  Only the pointer has to be remade -- a fresh Windows has no .claude
  folder. The memory itself already arrived with your project.

  Got a lot of projects? Menu option 3 links every project under one
  folder in a single pass, so you don't visit each by hand.


THE MENU
--------
  SETUP -- the only one you need
    1  Make this project's memory portable
         Moves the memory into this project and points Claude Code at it.
         Run it on a fresh project or after a Windows reset - it works out
         which is needed. Safe to pick again; it just says "already linked".

  EXTRAS -- optional
    2  Check status
         Shows whether this project is linked and how many memory files it
         has. Changes nothing, so it is always safe to look.

    3  Link every project under a folder at once
         Asks for a folder, finds every project under it that already has
         memory inside, and links them all. The bulk version of option 1 for
         after a reset. It cannot set up a project for the first time --
         there is nothing to find until option 1 has run once.

    4  Undo - put the memory back under your profile
         Removes the pointer and copies the memory back to the default
         location, returning Claude Code to normal behaviour. Your project
         keeps its copy too, so nothing is lost either way.

    0  Exit
         Closes the menu. Nothing is changed unless you picked 1, 3 or 4.

Prefer switches?  -Link  -Status  -Unlink  -Scan <dir>  -ProjectPath <dir>

No admin needed. Safe to re-run anytime -- it repairs what's wrong, skips
files that are already identical, and never overwrites a memory file (a
genuine conflict is kept beside it as *.from-profile.md).
